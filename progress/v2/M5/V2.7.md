The OS display is 100% scaling / 96 DPI. The 1.5× values are injected monitor/render-scale fixtures, not an OS scaling change. V0.3 recorded 20 first-use drops and selected native compact rendering in V0.4. §6.7 asks for frame measurement and comparison; the larger-WebView budget result remains visibly failed, rather than being converted to a zero-drop/pass result. Native idle/live composition has no WebView2/CDP target. Its motion unit tests, stable quiet commits, HWND geometry and ownership checks do not establish unmeasured zero-drop native frames.

Cold allocation exposed real readiness/lifecycle races. Instructions now distinguish an unshown surface; the frontend prepares deferred chunks/fonts after allocation and applies only the latest shown generation after native visibility/activity are known. A compact prepaint seeds the larger morph. Native opacity has one DOM owner, so React rerenders cannot silently restore opacity zero. The input observer publishes only after readiness and clears only its own rectangle. Stale view IPC/compact acknowledgements cannot mutate or destroy a newer view, and teardown preserves a physical held drag. Cancelling a cold drag before any web geometry is prepared completes the native-owned handoff without waiting for a page paint acknowledgement; prepared/painted views retain animated closing. A new allocation waits for the old WebView registration to disappear; its destruction callback wakes the deferred open. A lifecycle regression test covers close/reopen while the old registration still exists. Native Drop instructions preserve the React return state across repeated acknowledgements, so cancellation restores Expanded/Peek instead of spuriously collapsing. Regression tests cover these cases. An in-memory CapturePreview experiment showed no useful motion improvement and was removed; its failed measurements remain under `v27-native-preview-*`.

Idle diagnostics found unnecessary foreground-location traffic and repeated taskbar-message registration. The high-volume location hook was removed after a later same-foreground run still consumed 0.3% on the UI thread; filtering callbacks did not eliminate their delivery cost. The registered TaskbarCreated message is cached. The normal foreground/move/minimise hooks and 500ms notification fallback remain. The idle collector uses one fixed injected cursor without repeated file metadata reads; changing-cursor smokes retain the normal provider. Dynamic fixture reads retry transient Windows replacement I/O with at most four 1ms retry delays; malformed data still fails closed. A concurrent writer/reader probe retained failures for both replacement strategies in `v27-cursor-writer-probe.json`; the failed held-drag run and all motion attempts are indexed in `v27-development-attempts.json`. Earlier attempts rounded to 0.4%, 0.7%, 0.2%, 0.1% and 0.1%; all are retained. The separate fresh result does not rewrite V0's historical 0.1%-of-one-core failure.
