# V2.6 — Keyboard and explicit focus

Alt+Space opens/collapses the island on the cursor's monitor, including a maximised/faded monitor. Ctrl+1–6 selects and focuses the six tabs. Alt+1–9 opens the corresponding persisted pin slot and collapses on success. Typing from a nonediting control opens Search without losing the first word while its lazy component mounts. Existing text fields retain normal editing, Space activates buttons, AltGr text enters Search, and IME composition/Enter cannot accidentally launch a result. Search supports arrows/Enter, named combobox/listbox options and real pin/clipboard providers. Escape collapses; tab, query, filters, draft and scroll memory survive WebView destruction. Tab/Shift+Tab wrap through visible enabled controls. Icon actions have tooltips and accessible names; focus is visibly outlined.

The additive `islandShortcut` setting defaults to Alt+Space on Windows and can be remapped or disabled. Field-specific deserialization preserves old settings and all three legacy shortcuts. Saving rejects malformed/duplicate bindings and registers a replacement before persisting, so an OS registration conflict retains the prior binding. A startup conflict appears in the field. The field commits on blur/Enter, preserves rejected edits and ignores composition Enter. It reuses the existing Settings Field; the full Figma Shortcuts page/recorder and legacy-shortcut migration remain V6.4. Search follows Figma `34:777` and the existing `10:519` shell. Its complete tools/notes/links/shelf registry remains V5.7; fixture rows occur only in the screenshot harness.

Focus requests originate only from explicit hotkeys/clicks. The native manager records the previous HWND/process, issues a generation-scoped DOM focus hint and attempts foreground acquisition once per request. It retains `WS_EX_NOACTIVATE` throughout; background events and hover never request activation. Stale readiness cannot activate a replacement view, foreground changes cancel pending acquisition, and loss of an acquired foreground closes without stealing it back. Collapse restores the valid previous window only while the island still owns foreground. Denied activation is not retried until another explicit request. Own full-app windows are valid return targets. WebView2 receives programmatic focus after successful HWND acquisition, with another foreground check in the controller callback. This follows Microsoft's [explicit-activation behavior for WS_EX_NOACTIVATE](https://learn.microsoft.com/en-us/windows/win32/winmsg/extended-window-styles) and [WebView2 controller MoveFocus contract](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2controller?view=webview2-1.0.3856.49).

The minimal pins adapter adds the handoff schema, nullable unique slots 1–9, read/resolve/touch operations and an explicit opener. It validates an absolute existing path and matching file/folder kind before opening on a dedicated STA thread using ShellExecuteExW. No command string is assembled. Pin editing/drop-to-file remains V5. Background activity cannot open pins or start downloads.
