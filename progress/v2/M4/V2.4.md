# V2.4 — Activity bus, priority queue and island reducer

Rust owns the typed `ActivityEvent` contract, activity priority, per-monitor views and alert lifetimes. Messages on both `nabbit://activity` and `nabbit://island` retain the top-level camel-case event fields and carry a target label plus a versioned canonical snapshot. Consumers reject older revisions; one monitor's drag cannot open another monitor's surface. The existing clipboard and download paths publish through this bus without starting work from an activity event. Other service producers remain in their scheduled phases.

The default order is privacy, timer ending below 60 seconds, download, tool, link, transient result, media, running timer, then power. A view has at most one primary and one bubble; the remaining items wait. A link becomes bubble-only after eight seconds and disappears on clipboard change. Success/note/result alerts receive four seconds of actual primary-or-bubble exposure. Alerts behind both slots or hidden on every monitor wait without spending their display time. Exposure on any monitor counts as seen, so an alert already shown elsewhere is not replayed on a formerly fullscreen monitor. Errors remain until dismissed or replaced by retry progress. Disabled alert categories discard queued/new alerts; enabling them does not replay old notifications. Activity order, disabled categories, fullscreen-alert preference, Focus mode and the one-hour UTC hide deadline persist in the existing settings row.

One Rust condition-variable scheduler sleeps indefinitely without a deadline. It wakes for producer/configuration changes, link shrink, visible alert expiry or user-hide expiry. Native clock/power messages refresh wall-clock suppression, and refresh/shutdown synchronize with the wait lock. Repeated unchanged cursor/monitor samples do not wake this scheduler. Global hide and Focus mode override every alert; fullscreen permits only timer-ended and download-failed alerts when explicitly enabled. Such exceptions stay compact and click-through. Faded idle becomes visible for a live primary or a drag; hidden always cancels drag. Suppression cancels old hover/explicit wake so a maximised window restores faded idle. Native opacity and input remain on the UI thread without HWND resizing or focus calls. Visibility revisions stay monotonic when a host is removed/recreated.

The Zustand reducer owns presentation transitions and remembered tab, filters, search text and per-tab scroll. It covers hidden/idle/live/peek/expanded/drop/faded, alert replacement and return, stale snapshot rejection, target scoping and missing-host teardown. Continuous live hover opens Peek at 180ms; leaving closes it at 300ms and re-entry cancels that close. Expanded stays open until collapse. Drop returns to the prior valid surface. Versioned per-label local storage retains panel memory through WebView recreation, with corrupt/unavailable storage handled safely. Its connection subscribes before snapshot, disposes late subscriptions and schedules only live-hover/Peek-leave timeouts; idle/faded/hidden have no JavaScript timer. The idle entry connects the store without importing the main application store.

Design behavior was checked against Figma [state machine 23:495](https://www.figma.com/design/tBm7NNhh1Y9aTQPJ3WxY5v/Nabbit?node-id=23-495). The handoff's persistent-error rule takes precedence over the diagram's generic four-second alert caption. Compact content, Peek/Expanded/Drop rendering and motion/window handoff remain V2.5; keyboard bindings remain V2.6 and full §6.7 acceptance remains V2.7. Current native input can report unknown drag kinds until payload capture/routing is implemented. Error mapping remains V3.6; the existing downloader currently publishes `Unknown` failures. No new artwork, runtime dependency or dependency version was introduced.
