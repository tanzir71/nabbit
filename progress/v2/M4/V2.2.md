# V2.2 — Hit rectangles, adaptive input and drag band

Production native hosts now share V0's pure interaction policy. Each monitor keeps its own padded hit rectangle and input state. Cursor coordinates are converted from physical desktop pixels through the host origin and combined DPI/user scale into the reference 720×460 frame. Fractional-DPI edge comparisons allow a negligible floating-point tolerance, preserving inclusive edges on negative-origin monitors.

The default hit rectangle comes from the rendered native idle geometry. A mounted island WebView2 may override it through `island_set_hitrect`; `island_clear_hitrect` or window destruction restores native geometry. These commands and `island_set_drag` accept only the caller's active island label; the tray cannot update another surface. The old optional spike uses `island_spike_set_hitrect`, retaining its separate controller. Local island event subscriptions have a dedicated capability.

One Rust worker samples all active hosts. It requests a 25ms period within 120 reference pixels of any target, otherwise 500ms, and sleeps without polling when no hosts exist. A foreground WinEvent wakes it. The existing mouse hook also supplies exact button/band-boundary samples, so a fast held drag can be armed before the next far poll. Poll waits account for processing time rather than adding that time to the requested period. Acceptance cursor data is injected through `NABBIT_ACCEPTANCE_CURSOR`, cached until the fixture file changes, and never falls back to the real cursor on missing/invalid input. Legacy acceptance sessions without this provider keep input watching disabled.

Held-button entry into the top 48px band selects the padded 640px drop target; leaving, releasing or cancelling restores the original rectangle. The HTML5 bridge tracks supported URL/file/text drag lifetimes without consuming their payloads. Rust emits `nabbit://island-interaction`, `island:drag-enter` and `island:drag-leave` with a monitor label and typed decision. Hidden/faded input gates always pass clicks through. Actual fullscreen/maximised detection is V2.3; activity arbitration is V2.4; production drop visuals, larger-surface ownership and payload actions belong to their later tasks. The full §6.7 acceptance boxes remain pending.

The frontend bridge measures after ResizeObserver/layout events, adds 8px reference padding, normalizes user size once, coalesces redundant measurements and serializes slow IPC while keeping the latest layout. It schedules no idle interval or animation-frame loop. Cleanup avoids stale clears after replacement, clears hidden geometry even after an IPC failure, and lets a replacement view finish an active drag. The native compact renderer still allocates no WebView2 in normal idle use.

## Windows focus invariant

Testing exposed a framework side effect: Tao's cursor-event flag setter re-shows visible windows with `SW_SHOW`. It can activate an otherwise non-focusable WebView2 host. Production input updates therefore change HWND extended styles on the UI thread directly, retaining layering and nonactivation without a show/focus call. The acceptance view is shown with `SW_SHOWNOACTIVATE`. Lazy tray construction explicitly starts unfocused; an explicit user open still calls the existing reveal/focus path.

The foreground hook records Nabbit activations, including brief ones between polling checks. The smoke asserts zero such events and no sampled foreground HWND owned by Nabbit. It records unrelated desktop foreground changes separately rather than attributing them to the island. The previously recorded helper-activation restriction is unchanged; no keyboard injection or foreground-lock setting change is used.


The native smoke creates isolated SQLite/WebView2 profiles under ignored `.tools/`, refuses to disturb an existing Nabbit process, injects monitor/DPI/cursor fixtures, disables OS integrations and checks that no download was started. Its actual WebView2 driver checks served entry bytes against the current build, ResizeObserver geometry, command caller validation, typed drag events and polling frequency. Browser captures refuse to overwrite existing evidence; change their prefix or use a clean evidence directory for another run. No real cursor, display scaling/theme, authentication, installer or signing step is needed.
