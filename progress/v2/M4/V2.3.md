# V2.3 — Foreground detection and visibility

The production island now classifies foreground state separately from rendering and input. A pure policy consumes physical foreground/monitor rectangles, maximisation, visibility/cloaking, shell/own-process flags and `SHQueryUserNotificationState`. The Windows provider reads DWM extended frame bounds with a `GetWindowRect` fallback and rejects a read if the foreground HWND changes partway through. It collects no window titles or executable paths.

Only the foreground's monitor is suppressed. Shell, own-process, invisible, minimised and cloaked windows are excluded. Notification states Busy/D3D fullscreen/Presentation hide first; maximised windows fade next; other full-monitor borderless windows hide. A maximised window remains faded when an auto-hide taskbar lets its frame fill the monitor. Physical edges tolerate one pixel of rounding. Foreground, location, move-end and minimise events wake the existing Rust worker; a 500ms fallback handles notification-state changes without an event. The worker still sleeps without active hosts.

Hidden uses root DirectComposition opacity **0**, faded uses **0.35**, and both pass clicks through. HWNDs stay shown/composited and keep their bounds, topmost/tool/nonactivation styles. New hosts classify and apply opacity before first show. Unchanged opacity commits nothing. The existing raw HWND style path avoids Tao's activating show side effect.

Continuous top-band hover wakes a faded island after **400ms**. Leaving the band/hit rectangle or changing foreground resets hover wake. The band also works beyond the compact pill's 120px sampling radius: pending intent requests 25ms samples, and real mouse-hook band crossings supply exact boundary input. A caller-scoped `island_wake` command supports explicit wake and cannot override fullscreen. Alt+Space binding/focus behavior remains V2.6; activity arbitration, user hide and Focus mode remain V2.4. The full §6.7 acceptance checkboxes remain V2.7.

WebView2 receives typed `nabbit://island-visibility` events. Its bridge subscribes before fetching the snapshot, rejects stale revisions and other monitor labels, and changes only opacity, pointer handling and accessibility visibility. It starts transparent until a matching state arrives and disposes subscriptions even if setup resolves after teardown. No JavaScript interval or animation-frame loop was added. Normal compact use still allocates no WebView2.

```powershell
npm run verify
npm run verify:site
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets --features island-spike -- -D warnings
cargo test --manifest-path src-tauri/Cargo.toml -- --test-threads=1
cargo build --manifest-path src-tauri/Cargo.toml --release --features custom-protocol
node scripts/capture-island-visibility.mjs
./scripts/windows-island-visibility-smoke.ps1
```

The smoke creates isolated app-data/WebView2 profiles under ignored `.tools/`, refuses to disturb an existing Nabbit process, injects foreground/monitor/DPI/cursor fixtures and disables OS integrations. It additionally runs the foreground provider read-only on the current desktop. Captures use only the exact owned HWND or isolated browser page. The browser harness refuses existing output; use a clean evidence directory for reproduction. No human test, sign-in, installer or signing step is required.
