# V1.5 — capsule mark and desktop icons

The seven original SVG exports from [Figma Logo / Mark, 12:478](https://www.figma.com/design/tBm7NNhh1Y9aTQPJ3WxY5v/Nabbit?node-id=12-478)
are in `src/assets/brand/`, with node IDs, intrinsic dimensions and SHA-256 pins.
The five app tiles are 16, 24, 32, 64 and 128 px; tray glyphs are 16 and 24 px.
The light preview reproduces the 506×186 component-set arrangement. App tiles
retain the capsule/live-dot design in either appearance. The tray header now
uses the original 32 px tile instead of the old letter block.

`npm run icons` uses the existing locked Tauri CLI to rasterize the SVGs, without
editing their geometry. Small sizes use their individual optical variants.
Desktop PNGs cover 16–1024 px; the Windows ICO has seven PNG frames, and ICNS
has seven standard PNG-backed sizes. The 48 px frame renders the 24 px variant
at 2×; sizes above 128 render the original 128 px SVG at the requested resolution.
`npm run verify:icons` regenerates into ignored temporary folders and compares
every output, including source pins and the site copies. It is part of `verify`.
No dependency was added; the native dependency only enables registry/security
features on the already used `windows-sys` crate.

Windows reads `SystemUsesLightTheme`, independently of `AppsUseLightTheme` and
Nabbit's saved preference. A single native thread blocks on registry-change and
shutdown events; it never polls. Notifications re-arm before reading, unchanged
themes do not redraw, and shutdown signals and joins the worker. The original
glyph alpha is tinted ink on light taskbars or white on dark taskbars, avoiding
premultiplied edge RGB rounding. The taskbar's current DPI selects the 16/24 px
optical variant at startup and on theme updates. macOS uses the monochrome OS
template flag; macOS/Linux execution is not verified on this Windows machine.
General monitor/DPI lifecycle handling remains with the later island tasks.

The site uses a byte-identical original 32 px SVG and ICO fallback on the landing,
demo and custom 404. The 404 base URL keeps both favicon URLs valid at arbitrary
nested missing paths. All four production HTML entries also have the new mark
as a local favicon; there are no temporary Figma runtime URLs.

Automated evidence:

- `npm run verify`: 36 tests, typecheck, lint, asset checks and production build.
  Island initial JS remains **46,346 / 120,000 gzip bytes**; tray is 73,459 bytes.
- Rust: 39 tests, formatting, default and spike-feature Clippy with warnings
  denied, and an unsigned native feature/custom-protocol build. The real
  registry notification test writes only a disposable `Software\Nabbit\Tests`
  fixture key, deletes it, and verifies independent system/app values, both
  switch directions, duplicate suppression, idle waiting and idempotent stop.
  Glyph tests verify both optical sizes, alpha preservation and monochrome tint;
  missing/invalid values retain the Windows 10 dark-taskbar fallback.
- `v15-brand-checks.json`: four light/dark × 1×/1.5× browser contexts, all seven
  original SVG trees and intrinsic/rendered sizes, the app header, and decoded
  base-path favicon responses on the landing, demo and nested 404. No runtime
  errors or external requests. The first-run mock dialog is acknowledged before
  header capture, so it does not dim or obscure the mark.
- `v15-icon-resources.json`: read the compiled PE icon group as data and compare
  all seven embedded PNGs byte for byte with the generated assets. Windows
  decodes each through `CreateIconFromResourceEx`; every HICON is destroyed.
  Fourteen resource/Win32-decoded PNGs contain no desktop capture.
- `v15-native-entry-checks.json` / `v15-native-smoke.json`: the real isolated,
  hidden Windows WebView2 serves all four packaged entries, retains saved
  appearance/other settings, and starts no downloads. No focus, Windows theme,
  scaling, autostart or shortcut changes. The native tray capture shows the mark.
- `v15-capture-validation.json`: independent Pillow ICO/ICNS decoding, original
  favicon parity, actual light/dark/live-dot/header pixels, native alpha and
  composite pixels (maximum channel difference **0** on light/dark backgrounds),
  and hashes/size budgets for all **28 PNGs**, each below 300 KB. The mark and
  packaged icon were visually compared with the Figma screenshot.
- `npm run verify:site`: base paths, links/assets, 13 milestone rows, pre-release
  CTAs, demo and 404 still pass (41,866 bytes excluding fonts).

Reproduce without changing Windows settings:

```powershell
npm run verify
npm run build:components
node scripts/verify-brand.mjs
npm run build
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
cargo test --manifest-path src-tauri/Cargo.toml -- --test-threads=1
cargo clippy --manifest-path src-tauri/Cargo.toml --features island-spike --all-targets -- -D warnings
cargo build --manifest-path src-tauri/Cargo.toml --features island-spike,custom-protocol
.\scripts\windows-icon-resources.ps1
.\scripts\windows-theme-smoke.ps1 -OutputPrefix v15 -Verifier verify-native-entries.mjs
python scripts/verify-brand-captures.py --native
npm run verify:site
```

The native smoke uses fresh app-data/WebView2 profiles and disabled engine
updates. Theme switching is tested through owned fixture keys, never by changing
Windows preferences. This task does not remeasure or change the recorded M1
performance limits. M2 publication waits for V1.6 and the milestone pass.
