# V1.6 — reusable Playwright screenshot harness

`npm run screenshots -- --milestone M2 --prefix <unique-name> --repeat-check`
builds the existing component preview and production entries, starts an owned
loopback Vite preview and captures an explicit scenario registry through one
runner. [Usage and extension points](../../../scripts/screenshots/README.md)
are documented alongside the harness. Playwright 1.65.1/core are locked development
dependencies, replacing the requirement to install them in an ignored tools
folder. The screenshot command needs a Chromium browser installed through
`npm run screenshots:install`; the normal verify command does not need browsers.

Every scenario uses a new nonpersistent browser context, light/dark system
appearance, device scale 1 or 1.5, reduced motion, fixed Date, en-US locale and
UTC timezone. Data fixtures install a mock native IPC bridge before app loading.
The real frontend Tauri JS API exercises metadata/window labels, theme queries,
events and cleanup; unknown commands fail explicitly. No native app, clipboard,
downloader, user profile or OS preference is touched. Fixture data is cloned
across native-style responses and reset per context. Download progress starts
at 37% and the scenario pushes an event after changing it to 68%.

State-specific readiness, font/image decoding, disabled capture animations and
hidden carets settle screenshots. Device-pixel PNG dimensions and the 300 KiB
budget are enforced before publication. Repeat-check captures twice and requires
identical SHA-256. The runner records renderer/tool versions, build/fixture hashes,
actual custom Geist faces, dimensions, theme resolution and IPC calls. External
requests/WebSockets, failing resources, console/page errors, browser downloads,
dialogs and popups fail the suite. It closes contexts, Chromium and the owned
preview on success/failure, and identifies scenario/theme/scale in failures.
It refuses existing filenames and publishes nothing until all scenarios pass.

The `all` suite has seven scenarios, each captured in four contexts:

| Scenario | Entry/target | Evidence |
|---|---|---|
| Download queue/history | `index.html` | Fixed jobs, pushed progress; no download command |
| Clipboard | `index.html` | Fixed text/link entries, deterministic 5m/12m ages |
| Settings | `settings.html` | System preference and independent native theme query |
| Unbound sticky | `sticky.html` | Correct appearance at 280×208; no invented note |
| Idle island | `island.html` | Figma `7:2`, 112×26/r13 at y=6, always dark/transparent |
| Brand | `#brand-foundations` | Figma `12:478`, seven original optical variants |
| Controls | `#core-foundations` | Existing Figma `5:408` components |

Automated results:

- `v16-screenshots.json`: all **28 PNGs**, with identical repeat captures,
  complete mocked IPC and no runtime/network failures. Largest PNG: **62,754 bytes**.
- `v16-validation.json`: independent Pillow PNG decoding, complete matrix,
  dimensions/hashes/budgets and actual theme pixels. All island captures retain
  transparent corners/dark pill pixels and are byte-identical across system
  appearances. Brand PNGs exactly match the Figma-reviewed V1.5 captures. Brand,
  controls and representative tray captures were visually reviewed; this harness
  captures existing interfaces without claiming later full tray/widget layouts.
- `v16-preservation-check.json`: an actual duplicate-prefix invocation fails
  before starting a preview and leaves all 30 then-existing artifacts unchanged.
- `v16-failure-check.json`, `v16-parameterized-failure-check.json`: intentional
  console error and outbound request are blocked/rejected, the failure identifies
  its context, no failed evidence is published and all owned resources close.
  The second run verifies configurable milestone/prefix arguments.
- `npm run verify`: **43 frontend/script tests**, typecheck, lint, source-asset
  checks and the default four-entry production build. Seven new tests run through
  the actual Tauri API and cover fixture cloning/reset/save, native theme/window
  labels, domain events/unlisten, no-op copy, explicit backend failures, unknown
  command/download rejection, path guards, physical dimensions and PNG budget.
- Rust formatting, default Clippy with warnings denied and **39 Rust tests** pass.
  No Rust or production frontend code changed in this task. The screenshot harness
  and Playwright do not appear in any emitted production JS module graph; initial
  island JS remains **46,346 / 120,000 gzip bytes**. `npm run build` restored the
  default four entries after capture. See `v16-build-validation.json`.
- `npm run verify:site` still passes at 41,866 bytes excluding fonts. The new
  Playwright packages have no npm advisories; the existing project advisory totals
  were inspected without unrelated dependency updates.

For a fresh reproduction, choose an unused prefix and follow the harness README.
The independent raster audit uses the workspace's existing Pillow installation.
Historical task-specific verifiers and captures are retained. Native window
lifecycle, future modules/layouts and the recorded M1 performance limitations
are outside this task. M2 bookkeeping/publication is the next pass.
